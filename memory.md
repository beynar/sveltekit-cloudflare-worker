# Procedural Memory

- For prerelease reproductions, pin coupled dependencies from the release tag's lockfile. A broad peer range can admit later prereleases with incompatible runtime APIs; verify the exported symbol that failed before changing versions.
- Validate local infrastructure integrations with the real development command soon after static checks. Type-safe resource inputs can still fail in local provider conversion, authentication bootstrap, or the bundled runtime's compatibility-date boundary.
- When a framework and a Worker plugin share one Vite server, identify which plugin owns request serving separately from source transforms. Keep the framework transforms, remove only a competing Node request bridge, inline dependencies that workerd cannot load from the host filesystem, and prove the boundary first with a handler that does not touch application or binding code.
- When testing local binding parity across processes, verify namespace identity through alternating callers and a full restart. Matching binding names or types do not prove that both callers reach the same persisted resource.
- Do not infer that a new adapter plugin hook removes a framework-runtime fork. Trace who owns request execution and manifest generation separately; test the framework's public emulator or platform hook before reproducing private runtime plumbing.
- Validate a WebSocket bridge with bidirectional messages, a clean close handshake, and a process restart. Ordinary proxied `fetch` success does not prove that an upgrade response or persistent connection crosses the same boundary.
- Put implementation-only runtime packages in `dependencies`, not in the consumer installation command. Keep only host framework singletons and user-facing CLIs as peers, then verify the packed manifest and transitive type resolution.
- An adapter Vite hook cannot change the enclosing SvelteKit configuration before SvelteKit validates it. When integration requires replacing `files.hooks.server`, use a small configuration decorator, preserve the user's path, and keep runtime behavior in adapter-owned plugins.
- For a new workerd handler behind an older compatibility-date ceiling, distinguish the process `--experimental` switch from the Worker compatibility flag. Apply the compatibility flag only to the user service that needs it; simulator services can already include the flag and reject duplicates.
- When Arnaud asks for the same demo, preserve the exact feature contract, interactions, and backend capabilities before changing presentation. Compare the source page and its live endpoints directly; a visually related subset is not equivalent.
- Do not label a transient development-runtime failure as an HMR limitation after several files changed. Isolate which file transition triggers it, prove the updated module loaded on both runtime sides, and verify the live cross-runtime resource before reporting a limitation.
- A development-only adapter bridge must not validate unsupported simulator features during package construction. Defer those failures to the serve lifecycle, then prove that the same Wrangler configuration can still reach the production builder.
- Do not infer Cloudflare entrypoint classes from export names alone. Bundle first, classify actual class bindings, and keep ordinary named values out of the final Worker export map; workerd validates that map at startup.
- Framework adapter tests must model the current public builder contract, even when the delegated adapter is mocked. A partial mock that omits a newly required object can make a valid compatibility boundary look broken, or hide that the boundary was never exercised.
- Resolve a user-selected project root and configuration file once, then pass the same absolute path to every delegated runtime and build owner. Testing only the local bridge can hide a production adapter that still resolves the file from the process working directory.
- Resolve relative fields inside an infrastructure configuration from the configuration file's directory, not automatically from the application root. A nested config can otherwise produce a valid build whose private modules are exposed as public assets.
- Vite's `serve` command includes both development and preview. Gate development-runtime plugins on `ConfigEnv.isPreview`, and test the standard preview command separately from a production-runtime preview.
- A framework emulator can be called before route configuration is known. Use build lifecycle state to keep dev-only resources out of every prerender call, and allow prerender platforms that intentionally omit an execution context.
- When integration fixtures symlink one dependency tree, give each Vite fixture its own `cacheDir`. A shared optimizer cache can invalidate another live server and create false HMR failures.
- Verify bundled ambient types from a strict-package-manager consumer, not only from the package repository. When a type package ships both `index.ts` and `index.d.ts`, a side-effect import can resolve the module-shaped source file; a type-reference directive can be required to install its globals.
